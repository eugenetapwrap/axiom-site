# Карточки отчётов Nota

Картинки-отчёты, которые бот присылает в Telegram. Четыре формата: архив, первые 30 документов, неделя, месяц. Языки ru, en, id; валюты IDR, VND, RUB, THB, USD, EUR, SGD. Как выглядит каждый формат в каждом языке и валюте — `examples/` (всё на одной картинке — `examples/overview.png`).

## Как запустить
1. Python 3.9 или новее (проверено 3.9, 3.11, 3.13 — результат одинаковый), без зависимостей. Для картинок — Node.js 18+ и Playwright: `cd generator && npm install && npx playwright install chromium` (ставится в `generator/`, см. `package.json`).
2. Проверка: `python3 generator/example.py` — четыре карточки на выдуманных данных в `generator/out/ru-IDR/`.
3. В коде бота:
   ```python
   import cards                      # generator/cards.py; шаблоны и fonts/ ищет в папке над generator/ (или NOTA_TPL_DIR)
   html = cards.period_card(rows, start, end, 'week', 'Имя аккаунта', loc='ru', cur='IDR',
                            prev_rows=rows, client_start=first_doc_date)   # прошлый период генератор возьмёт из rows сам
   if html is None: ...              # расходов нет — картинки нет, бот пишет текстом «нет расходов»
   else: open('card.html', 'w', encoding='utf-8').write(html)   # затем: node generator/render.cjs card.html card.png → PNG 2160 px
   ```
4. Когда какой отчёт:
   - архив — после разбора ZIP: `archive_card`;
   - первые 30 документов — когда закончились бесплатные 30, только с подключённым Google: `first30_card`;
   - неделя — в понедельник за прошлую неделю (пн–вс), месяц — 1-го числа за прошлый месяц: `period_card(..., 'week' | 'month')`;
   - отчёт по запросу внутри периода — тот же `period_card` с `report_date` = сегодня.

### Строка данных
Одна строка листа Payments — dict:
- `date` — дата документа (`date`, `datetime` или строка `2026-11-10`); без даты строка не попадает ни в неделю, ни в месяц, а в архиве и первых 30 считается, но не влияет на подпись периода;
- `amount` — сумма в валюте отчёта (число, `Decimal` тоже можно);
- `payee` — поставщик, пусто — «Не указан»;
- `cat` — категория как записана в таблице, без перевода; пусто — «Без категории»;
- `check` — `DBL` — дубль, в расходы не входит; `Review` — стоит проверить, входит; любое другое значение — как `OK`;
- `status` — `Rejected` — в расходы не входит;
- `type` — `Hand` — рукописный; `Statement` и `Proof` — в расходы не входят.

Пустые значения (`None`) можно передавать как есть. Текст поставщика, категории, имени аккаунта и файла экранируется: «<», «&» и любая разметка из документов выводятся как текст.

## Архив — утверждено основателем 17.11 («запомни карточку архива», «сохрани пока, запомни»)
`archive.html` → `archive.png` (1080 × 1350).
- Шапка: Nota · имя аккаунта · имя файла архива; плашка валюты (IDR). Плашку «Разобран» убрали (17.11).
- Над цифрой одна серая строка: «Расходы за 1–31 окт 2026 · архив получен 3 ноя» (17.11: объединены «Получен…» и «Расходы»).
- Итог — без дублей (решение 17.11, вечер: как в неделе и месяце; в плитке «1 дубль исключён»), справа число платежей и файлов, строка «Не вошли в расчёт».
- Три серые плитки (правка 17.11: вместо полосы): сумма — главная цифра, количество документов — под ней. Порядок: дубли → стоит проверить (обе суммы оранжевые) → рукописные.
- Категории — 7 строк (17.11: добавлены «Инструменты»), поставщики — 7, суммы в единицах валюты (млн / тыс. / код) и в сумме дают итог, «млн» серым в заголовке, зелёные полоски, «Без категории» оранжевым.
- Крупнейшие платежи — полные суммы, выровнены по левому краю (17.11).
- Заголовки блоков капсом, как в неделе и месяце (17.11): «КАТЕГОРИИ, МЛН», «ПОСТАВЩИКИ, МЛН», «КРУПНЕЙШИЕ ПЛАТЕЖИ» — 19 px, жирный, разрядка 0,08em, серо-синий; «МЛН» серым. От заголовка до первой строки (и до серой таблицы) 26 px.
- Отступы (17.11): между крупными блоками 40 px, строка над цифрой → цифра 4 px, заголовок блока → первая строка 26 px (как в неделе и месяце), внизу ~50 px до подписи.
- Данные тестовые. В шаблонах шрифт подключён из `nota/public/fonts/` абсолютным путём (чтобы открыть макет в репозитории сайта); генератор подставляет папку `fonts/` рядом с шаблонами, так что пакет работает где угодно.

## Первые 30 документов — согласовано с основателем 17.11
Приходит, когда закончились бесплатные 30 документов (только с подключённым Google). Строится по первым 30 строкам листа Payments.
- Шапка и верх — как в неделе: Nota · имя аккаунта · валюта; подпись «Расходы по первым 30 документам · 14–26 сен 2026»; отступы 18 / 40 / 126 / 20 px, как в неделе (основатель: «сделай как в недельной»).
- Справа «28 платежей из 30 документов».
- Тело — как в архиве: три плитки (дубли → стоит проверить → рукописные), категории и поставщики по 7 строк, крупнейшие платежи.
- Строки «Не вошли в расчёт» нет: отчёт строится по таблице (основатель, 17.11). Сравнения нет: прошлого периода у клиента нет.
- Нет расходов (все строки — дубли или отклонены) — карточки нет.

## Неделя и месяц — утверждено основателем 17.11
Генератор собирает и неделю, и месяц из `week.html` (тот же каркас, в месяце график на все дни месяца); `month.html` — макет месяца для просмотра, генератор его не использует. Вёрстка 1080 px, в макетах тестовые данные.
- Шапка: Nota · имя аккаунта · код валюты. Над цифрой серая строка «Расходы за неделю · 26 окт – 1 ноя 2026» / «Расходы за месяц · октябрь 2026».
- Справа: среднее за день, под ним сравнение «−5% к прошлой неделе · 30,64 млн» / «+11% к сентябрю · 1 110,00 млн».
- Полоса: учтено документов → ожидают проверки (оранжевый) → дубли исключены (зелёная плашка).
- «ПО ДНЯМ, МЛН» (бирюзовый график, день-максимум тёмный с подписью, «без категории» оранжевым) и «КРУПНЕЙШИЕ ПЛАТЕЖИ» (сумма, справа компания, под суммой дата).
- Категории и поставщики по 8 строк, суммы в единицах валюты, у категорий изменение к прошлому периоду.
- Заголовки блоков капсом 19 px, разрядка 0,08em; от заголовка до первой строки 26 px.

## Правила для реальных данных (17.11)
- Изменения у категорий — в единицах валюты к прошлому периоду: «Ремонт +1,05», «Расходники −3,50» (вместо процентов и «×N»; панель не понимала «×17 чего?»). Цветом — только самый большой рост (оранжевый) и самое большое снижение (зелёный), остальные серые; изменения, которые после округления дают 0 (меньше 0,005; у USD, EUR, SGD — меньше 0,5), не показываем; от 1 000 единиц — без копеек («+3 890»).
- Отчёт по запросу внутри периода считает документы по день отчёта включительно и сравнивается с теми же днями прошлого периода (понедельник с понедельником, 1–12 ноября с 1–12 октября), и итог, и категории.
- Прошлый период генератор выбирает сам: в `prev_rows` можно передать все строки клиента.
- Прошлый период у клиента неполный (подключился позже его начала, `client_start` позже первого дня прошлой недели или месяца) — сравнения нет, как и без данных: «+114% к сентябрю» при сентябре с 14-го вводит в заблуждение (решение 17.11, можно изменить).
- Общий итог к прошлому периоду: до +200% — «+73%», от +200% (после округления) — «×N», не больше «×99+»; рядом сумма прошлого периода.
- Округление везде — половины вверх: 2,5 → 3, 24,465 → 24,47.
- Нет данных за прошлый период — ничего не пишем (ни строки сравнения, ни изменений у категорий): фраза «за сентябрь данных нет» путает (основатель, 17.11).
- Среднее за день: плановый отчёт (неделя — в понедельник, месяц — 1-го) делит на все дни периода; отчёт по запросу — на дни до сегодняшнего включительно (4-й день недели — на 4). Первый период клиента — считать с первого документа.
- Первый период клиента: к подписи «· данные с 17 окт».
- Пустые показатели — только серый текст, без «0»: «Документов для проверки нет», «Дублей не найдено», в архиве «Рукописных нет».
- Высота карточки — по содержимому, но не меньше 1080 (квадрат); полные отчёты — 1080 × 1350. Подпись внизу всегда с отступом от содержимого.
- Итог: шрифт по длине числа (до 4 цифр — 120 px, 5 — 100, 6 — 84, больше — 72), без переноса; если вместе с правым столбцом (среднее, сравнение, число платежей) строка не помещается в поле — на ступень меньше (генератор оценивает ширину по таблице ширин Inter, запас 12 px); суммы в плитках тоже уменьшаются. Проценты в колонке в сумме 100 (наибольшие остатки); доля меньше 0,5% — «<1%» и в распределение не входит (тогда остальные дают сумму без неё); сумма меньше 0,005 единицы — «<0,01», и у итога тоже.
- График по дням: подпись — только у одного дня-максимума (первого, если таких несколько).
- Списки: не больше 8 строк (архив — 7); лишнее — «Остальные N». Без категории — «Без категории» (оранжевая точка); без поставщика — «Не указан» обычным цветом (это проблема, а не мелочь), в платежах — «Поставщик не указан».
- Длинные названия обрезаются многоточием; в шапке архива — имя аккаунта и файла тоже; категория в таблице крупнейших платежей — не шире 260 px.
- Нет расходов за период (всё отклонено или дубли) — карточки нет, вместо неё сообщение «нет расходов».
- Подписи периода: «9–15 ноя 2026», «30 ноя – 6 дек 2026», «28 дек 2026 – 3 янв 2027».
- Документы со статусом Rejected в расходы не входят; в архиве — «Не вошли в расчёт: N отклонённых документов» (считаются только Rejected; Statement, Proof и нулевые суммы — нет); если таких нет, строки нет.
- Первые 30: если передать больше строк, генератор берёт первые `limit`.
- Вне продукта (основатель, 17.11): бюджет и план-факт, разбивка по объектам (пока), кнопки под картинкой (в архиве и таблице есть Review и DBL).

## Языки и валюты
- Языки: ru, en, id — все тексты карточки в словаре `T`; месяцы и дни недели свои. Язык карточки (`loc`) — тот, что задан в таблице клиента.
- Категории генератор берёт из листа Payments как есть, без перевода: какие названия в таблице, такие и в карточке (основатель, 17.11). Язык категорий задаёт таблица. Своё название генератор пишет только для пустой категории: «Без категории» / «Uncategorized» / «Tanpa kategori».
- Числа: ru «1 230,45», en «1,230.45», id «1.230,45».
- Валюты (`CUR`): IDR, VND — в миллионах («млн» / «M» / «jt»); RUB, THB — в тысячах («тыс.» / «K» / «rb»); USD, EUR, SGD — как есть, а там, где у рупий «млн», стоит код валюты: «490 USD», «70 USD в среднем за день», «КАТЕГОРИИ, USD», «КРУПНЕЙШИЕ ПЛАТЕЖИ, USD» (основатель, 17.11: у итога всегда валюта, «$» путается между USD и SGD). Суммы целыми: итог, списки, среднее, сравнение, плитки, график и изменения без центов, сумма меньше 0,5 — «<1», изменение меньше 0,5 не показываем; крупнейшие платежи — точные, с центами, чтобы узнать документ (основатель, 17.11). Плашка в шапке — код валюты. Полные суммы платежей — без дробной части для IDR, VND, RUB, THB и с двумя знаками для USD, EUR, SGD.
- Проверено 17.11 после независимой проверки кода (14 замечаний исправлены): Python 3.9, 3.11, 3.13 — одинаковый результат; рендер без системных шрифтов — латиница, кириллица, вьетнамский и тайский из встроенных шрифтов; разметка в названиях выводится текстом; все 4 формата на всех 21 сочетании языка (ru, en, id) и валюты (IDR, VND, RUB, THB, USD, EUR, SGD) — 84 карточки; неделя на тех же 21 сочетании с суммами ×1000 и ×0,001, без прошлой недели и по запросу в среду — ещё 84; без переполнений и наложений, шрифт загружен, итог совпадает со списками, проценты дают 100; образцы в `examples/` — 8 сочетаний; стресс-набор архива, недели и месяца (20 случаев: огромные суммы, один документ, только дубли, без категорий и поставщиков, длинные имена, переходы через месяц и год, февраль, первый месяц, отчёт по запросу) и первых 30 документов (16 случаев: огромные и копеечные суммы, только дубли, всё отклонено, без категорий и поставщиков, длинные имена и категории, переход через год, все в один день, много категорий, другой бесплатный объём) — итог совпадает со списками, проценты дают 100.

## Генератор
`generator/cards.py` (v3) — собирает все четыре формата из строк листа Payments по шаблонам выше:
- `archive_card(rows, account, file_name, received_date, loc='ru', cur='IDR', files=None)` — `files` — число файлов в архиве (без него одна строка = один файл);
- `first30_card(rows, account, loc='ru', cur='IDR', limit=30)` — `rows` — первые 30 строк листа; `limit` — бесплатный объём, стоит в подписи;
- `period_card(rows, start, end, 'week'|'month', account, loc, cur, prev_rows=None, report_date=None, client_start=None)` — `prev_rows=None` значит данных за прошлый период нет; `report_date` — день отправки (для среднего за день); `client_start` — первый документ клиента.

Строка — dict: date, amount (в валюте отчёта), payee, check (OK / Review / DBL), status (Rejected — не входит), cat (название категории из листа Payments как есть; пусто — «Без категории»), type (Hand — рукописный). Возвращает HTML или None (нет расходов). Рендер — Playwright, вёрстка 1080 px, картинка в двойном разрешении: deviceScaleFactor 2 → 2160 × 2700 (решение основателя 17.11), у коротких карточек высота по правилу выше × 2.

### Источник данных: лист или база
Генератор сам ничего не читает: ни Google-таблицу, ни базу. На вход — список строк, откуда они, ему всё равно. Если данные будут в базе, программист пишет запрос, который отдаёт строки с теми же полями, шаблоны и правила не меняются.
- Поля: date, amount (в валюте отчёта), payee, cat (категория как записана, без перевода), check, status, type.
- Значения check, status и type — теми же словами, что в листе Payments: OK / Review / DBL; Rejected; Hand — рукописный, Statement и Proof в расходы не входят. Если в базе они хранятся иначе (числами, другими словами), перевести в запросе.
- Типы из базы генератор принимает как есть: Decimal, datetime, NULL (проверено 17.11).
- Прошлый период — тот же запрос за прошлую неделю или месяц. Пустой результат — то же, что «данных нет»: ни сравнения, ни изменений у категорий.
- Из настроек клиента: имя аккаунта, язык, валюта, дата первого документа (`client_start`); для архива — имя файла, дата получения, число файлов; для первых 30 — первые 30 строк клиента по порядку записи.

### Файлы пакета
- `archive.html`, `week.html` — шаблоны, которые использует генератор (вёрстка 1080 px): архив — `archive.html`, неделя и месяц — `week.html`, первые 30 — `archive.html` с шапкой и верхом `week.html`; `month.html` — макет месяца для просмотра; `archive.png` — утверждённый макет архива.
- `examples/` — образцы: 4 формата × 8 сочетаний языка и валюты, в 1080 px (в боте — 2160 px); `overview.png` — все на одной картинке.
- `fonts/` — Inter (кириллица, латиница, вьетнамские буквы) и Noto Sans Thai для тайских названий, лицензия SIL OFL 1.1. Генератор встраивает их в HTML (data:), поэтому картинка не зависит от системных шрифтов, путей и ОС; HTML можно открывать и через `page.goto`, и через `page.setContent`.
- `generator/cards.py` — генератор (Python 3, без зависимостей). Папку шаблонов можно задать переменной `NOTA_TPL_DIR`, по умолчанию — папка над `generator/`.
- `generator/render.cjs` — HTML → PNG: `node render.cjs card.html card.png [масштаб]`, по умолчанию 2 → 2160 px (нужен Playwright с Chromium). Высота по правилу выше, больше 1350 — ошибка, код выхода 2; шрифт не загрузился — код выхода 3 (вместо картинки другим шрифтом).
- `generator/package.json` — зависимость Playwright для `npm install` в этой папке.
- `generator/example.py` — пример на выдуманных данных: `python3 example.py` собирает четыре формата на русском в IDR в `generator/out/`; `--all` — все языки и валюты; `--scale 1` — в 1080 px.
